## 目标

为多店管家 Android APP 和 admin Web 后台提供统一的后端服务，实现用户鉴权、店铺管理、算力计费、交易日志、用户反馈等核心业务接口。

**范围**：`admin/backend/` 模块 Spring Boot 后端开发。不影响 `app/` Android 模块和 `Bcore/` 引擎模块。

#### Task 4: APK 上报店铺数据 + 自动扣算力
- **文件**:
  - `admin/backend/.../controller/ShopReportController.java`
  - `admin/backend/.../service/ComputeService.java` — 算力扣减核心服务（新增）
  - `admin/backend/.../service/ShopReportService.java` — 上报处理服务（新增）
- **接口规范**:
  ```
  POST /api/shops/report
  Headers: Authorization: Bearer {token}
  Content-Type: application/json

  Request:
  {
    "shopName": "美团外卖·xx路店",
    "shopId": "M123456",
    "platform": "meituan",
    "platformName": "美团外卖",
    "packageName": "com.sankuai.meituan.merchant",
    "remainingDays": 30,
    "autoRenew": true
  }

  Response (200):
  {
    "code": 200,
    "message": "success",
    "data": {
      "shopId": "M123456",
      "deducted": 1,          // 本次扣减算力
      "balance": 199,         // 剩余算力
      "isNew": false          // 是否新店铺
    }
  }

  Response (402):
  { "code": 402, "message": "算力不足，请充值", "data": null }
  ```
- **业务逻辑**:
  1. 从 token 解析 userId
  2. 根据 `shopId` + `userId` 查询是否已存在该店铺
     - **已存在**: 更新 `remainingDays` / `autoRenew` / `shopName`
     - **新店铺**: 插入新记录
  3. **算力扣减**:
     - 检查用户 `computeBalance` ≥ 1（每个店铺每天 1 算力，或按规则）
     - 不足 → 返回 402
     - 足够 → `computeBalance -= 1`，写入 `transaction_logs` 表（type=CONSUME）
  4. 更新用户 `shopCount` / `platformCount`
  5. 返回扣减结果
- **交付标准**:
  - 新店铺上报后正确扣减算力
  - 算力不足时返回 402
  - 重复上报同一店铺不重复扣减（同一自然日内）

#### Task 5: 算力赠送接口
- **文件**:
  - `admin/backend/.../controller/GiftController.java`（新增）
  - `admin/backend/.../service/ComputeService.java` — 补充赠送逻辑
  - `admin/backend/.../controller/dto/GiftComputeRequest.java`（已有）
- **接口规范**:
  ```
  POST /api/compute/gift
  Headers: Authorization: Bearer {token}
  Content-Type: application/json

  Request:
  {
    "toPhone": "13900139000",
    "amount": 50
  }

  Response (200):
  {
    "code": 200,
    "message": "success",
    "data": {
      "fromUser": "138****0000",
      "toUser": "139****0000",
      "amount": 50,
      "fromBalance": 150,
      "toBalance": 250
    }
  }

  Response (400):
  { "code": 400, "message": "赠送数量必须大于0", "data": null }

  Response (402):
  { "code": 402, "message": "算力余额不足", "data": null }

  Response (404):
  { "code": 404, "message": "对方用户不存在", "data": null }
  ```
- **业务逻辑**:
  1. 从 token 解析 fromUserId
  2. 校验 amount > 0
  3. 查询 fromUser，校验 balance ≥ amount
  4. 根据 toPhone 查询 toUser，不存在返回 404
  5. **事务**: fromUser.balance -= amount, toUser.balance += amount
  6. 写入两条 `transaction_logs`:
     - fromUser: type=OUT, amount=-50
     - toUser: type=IN, amount=+50
  7. 返回双方脱敏手机号和最新余额
- **交付标准**:
  - 赠送成功双方余额正确变更
  - 事务保证：一方失败全部回滚
  - 日志记录完整

## 统一响应格式

所有接口统一返回 `ApiResponse<T>`:

```java
public class ApiResponse<T> {
    private int code;       // 200=成功, 400=参数错误, 401=未授权, 402=算力不足, 404=不存在, 500=系统错误
    private String message;
    private T data;
}
```

**HTTP 状态码映射**:

| code | 含义 | 使用场景 |
|------|------|---------|
| 200 | 成功 | 正常返回 |
| 400 | 参数错误 | 校验失败、格式错误 |
| 401 | 未授权 | token 无效、密码错误 |
| 402 | 算力不足 | 扣减时余额不够 |
| 404 | 不存在 | 用户/店铺/记录未找到 |
| 500 | 系统错误 | 服务端异常 |

### 修订 3: shops 表新增防重字段（发现 2）

**变更**: `Shop.java` 实体新增两个字段：

**扣减逻辑**:
1. APK 上报店铺时，服务端检查 `expireAt` 是否在将来
2. 如果在有效期内 → 返回 `deducted: 0, balance: 不变`，店铺可用
3. 如果已过期：
   - 用户开启自动续期 → 自动扣减 1 算力，更新 `lastDeductedAt = now()`，`expireAt = now() + 30 天`
   - 用户未开启自动续期 → 返回 `402` 或标记为「已过期」，引导用户手动续费
4. 新店铺首次上报 → 扣减 1 算力，`expireAt = now() + 30 天`

### 修订 4: 算力扣减改为异步模式（发现 9）

**变更**: `POST /api/shops/report` 不再同步阻塞 APK。

**新流程**:
1. APK 点击店铺 → 立即 `EngineProxy.launchApk()` 启动分身
2. APK 在分身中获取店铺信息后 → 异步调用 `/api/shops/report`
3. 服务端扣减算力并返回结果
4. 如果扣减失败（算力不足），APK 显示 Toast 提示，但不阻止用户继续使用

**影响**: `ShopReportController` 的响应不再影响 APK 启动流程，但需要在返回结果中明确 `isExpired` 状态。

### 修订 7: 新增批量验证店铺有效期接口

**业务规则**: APK 点击店铺前必须校验该店铺在服务端是否在有效期内。APK 本地缓存有效期数据最长 30 分钟，超时后重新请求。

**新增接口**:
```
GET /api/shops/validate?shopIds=M123456,M789012
Headers: Authorization: Bearer {token}

Response (200):
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "shopId": "M123456",
      "isValid": true,           // 是否在有效期内
      "expireAt": "2026-07-05T10:00:00",  // 有效期截止时间
      "autoRenew": true          // 是否开启自动续期
    },
    {
      "shopId": "M789012",
      "isValid": false,
      "expireAt": "2026-06-01T10:00:00",
      "autoRenew": false
    }
  ]
}
```

**业务逻辑**:
1. 解析 `shopIds` 参数（逗号分隔，最多 50 个）
2. 按 `user_id` + `shop_id` 查询 `shops` 表
3. 返回每个店铺的 `expireAt` 和 `isValid`（`expireAt > now()`）
4. 不存在的店铺返回 `isValid: false`

**新增文件**:
- `ShopValidationController.java`
- `ShopValidationResponse.java`（DTO）
