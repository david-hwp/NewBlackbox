# Phase 17 Wave 3: 店铺卡片微信接收方绑定与一键分享 - Plan

**Status:** Completed by scoped closure
**Created:** 2026-06-14

## Goal

在非微信平台店铺卡片上支持绑定一个微信分身接收方，并提供一键把测试文本分享到该店铺绑定微信联系人的入口。每个店铺卡片独立保存接收方信息，不把业务数据长期存在引擎目录。

## UI Scope

- 保留现有店铺卡片按钮栏里的“微信”按钮，用于打开分身微信分享选择器，让用户手动选择/绑定接收方。
- 在当前店铺卡片按钮栏上方新增一排功能栏：
  - 1 个“分享”按钮：读取该店铺已绑定的微信接收方并触发一键分享。
  - 5 个占位开关：差评定位、经营日报、外呼好评、评价申诉、私域吸粉。
- 每个开关从上到下展示：开关名称、开关组件、两个文本占位。
- 本 wave 中 5 个开关只做 UI 占位，不接后端、不保存状态、不触发业务逻辑。
- 微信平台自身店铺卡片不显示“分享”按钮和绑定入口，避免对微信卡片绑定自己。

## Data Flow

- 主 APP 发起绑定时调用引擎 AIDL 开启一次性微信分享目标捕获。
- 引擎在分身微信进程内从 `SendAppMessageWrapperUI`/相关跳转 Intent 读取 `Select_Conv_User`。
- 捕获会话必须注册在 `com.zhirang.zhanghaoguanjia.engine:black` 的 ActivityManager 服务进程；分身微信上报事件也进入该进程，不能依赖跨进程静态监听器。
- 引擎解析接收方名称后通过 AIDL 回调给主 APP。
- 主 APP 按系统店铺 ID 保存到私有目录：
  - `files/wechat-share-targets/shops/<systemShopId>/last.json`
  - 字段包括 `receiverId`、`receiverName`、`receiverType`、`packageName`、`localVirtualUserId`、`capturedAtEpochMillis`、`evidence`。
- 主 APP 卡片展示该店铺绑定的 `receiverName / receiverId / receiverType`。
- 引擎不长期保存这三个业务字段；捕获完成、超时、取消或错误后清理内存回调。

## One-Tap Share Behavior

- 用户点击“分享”按钮时，主 APP 读取当前店铺本地保存的接收方。
- 如果没有绑定接收方，提示用户先点击“微信”按钮绑定接收方。
- 如果有绑定接收方，主 APP 准备已登录微信分身环境，并通过引擎启动分身微信分享链路。
- 分享 Intent 必须带上目标接收方 ID（`Select_Conv_User`）和测试文本 `测试从店铺管家分享到分身微信`，目标是进入分身微信对应接收方的发送/确认链路，而不是系统微信。
- 如果微信分身环境准备失败、微信店铺不存在或接收方数据不完整，需要给出明确 Toast，不写入错误绑定数据。

## Acceptance Targets

- 美团第一张非微信平台店铺卡片点击“微信”按钮后，能够通过分身微信选择“贺伟平”，并把接收方写入主 APP 私有目录。
- 返回主 APP 后，美团第一张店铺卡片必须展示 `贺伟平 / wxid_4661706616414 / 个人微信`，展示位置在店铺 ID 下方。
- 美团第一张店铺卡片新增的“分享”按钮必须读取该店铺保存的接收方，并把测试文本 `测试从店铺管家分享到分身微信` 发送到“贺伟平”，不能走系统微信。
- 新增功能栏中的 5 个开关只作为占位展示，不影响现有店铺打开、修复店铺、微信接收方绑定和一键分享。
- 完整一键分享到微信联系人的验收依赖微信工具卡恢复有效登录态；当前 phase 将微信分享捕获链路和失败依据收敛为遗留研究项，后续重新打开时从 `RESEARCH.md` 的记录继续。

## Fix Scope

- 修复当前联系人无法展示的问题：`BlackBoxEngineService.startWechatShareCapture()` 不能使用本进程 `ServiceManager.getService()`，必须通过 `BlackBoxCore.get().getService(ServiceManager.ACTIVITY_MANAGER)` 获取 `:black` 远程 ActivityManager binder。
- 在 `BActivityManagerService.startWechatShareCapture()`、`dispatchWechatShareTarget()` 打印 PID 和关键字段，验证捕获会话与 dispatch 发生在同一 `:black` 进程。
- `WechatShareTargetStore.save()` 保存失败时需要可观测日志，避免静默失败导致卡片不显示。
