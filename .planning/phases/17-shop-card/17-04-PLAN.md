# Wave 4: 店铺卡片长按拖动排序

## 目标

支持 APP 首页同用户、同平台下的店铺卡片长按拖动排序。排序结果持久化到服务端，后续 APP 拉取店铺列表时严格按服务端返回的排序字段展示。

## 数据约束

- 服务端 `shops` 表新增 `card_sort_order` 字段，表示用户在同一平台下的店铺卡片排序序号。
- 排序业务只使用系统店铺 `id`，不使用平台内部 `shopId`。平台 `shopId` 只作为展示和记录字段。
- 排序接口只接受系统店铺 ID 列表，并校验这些店铺全部属于当前登录用户、同一平台/包名。
- APP 收到店铺数据后按 `cardSortOrder ASC` 严格排序，排序值相同时使用创建时间/系统 ID 兜底，避免顺序抖动。

## 服务端实现

- `Shop` 实体、初始化 SQL、启动迁移补充 `card_sort_order`。
- `ShopResponse` 输出 `cardSortOrder`。
- 新增 `PUT /shops/order`，请求体为 `{ "shopIds": [系统店铺ID...] }`。
- 新增店铺时默认排到同用户同包名最后。

## APP 实现

- `ShopDto` / `Shop` 增加 `cardSortOrder`。
- 当前平台店铺列表按排序字段展示。
- 长按任意店铺卡片进入排序模式：
  - 所有卡片轻微晃动。
  - 非当前拖拽卡片降低透明度。
  - 用户上下拖动目标卡片到新位置。
  - 释放后退出排序模式，恢复正常视觉状态。
  - 使用当前平台下所有可见店铺的系统店铺 ID 顺序上报服务器。
- 排序上报失败时提示用户，并重新从服务器拉取店铺列表恢复权威顺序。

## 后台管理

- 店铺管理列表展示 `cardSortOrder`。
- 编辑店铺时允许管理员直接调整排序序号，用于兜底修正。

## 验收

- 同平台多张店铺卡片可以长按上下拖动。
- 释放后 APP 立即保持新顺序，刷新后仍按新顺序展示。
- 服务端排序接口拒绝跨用户、跨平台、无效店铺 ID。
- 新增店铺默认出现在当前平台最后。

## 实施记录

- 服务端新增 `shops.card_sort_order`、启动迁移和 `PUT /shops/order`。
- 排序接口只接受系统店铺 `id`，并校验当前用户、同平台、同包名；平台 `shopId` 不参与排序业务。
- APP 首页长按店铺卡片进入排序模式，所有卡片轻微晃动，非拖拽卡片降低透明度；释放后退出排序模式并上报当前顺序。
- 后台店铺管理列表增加排序字段展示，编辑店铺时可手动调整排序序号。
