<threat_model>
  <assets>
    <asset>APK and engine release packages, checksums, and download URLs.</asset>
    <asset>Release worker auth token and callback permissions.</asset>
    <asset>Channel-scoped announcements and version visibility.</asset>
    <asset>Admin and channel-admin management UI actions.</asset>
    <asset>Unified file upload/download service and OBS/local storage paths.</asset>
  </assets>
  <risks>
    <risk>A release job could publish an artifact to the wrong channel.</risk>
    <risk>A leaked worker token could upload malicious APKs or complete another job.</risk>
    <risk>Concurrent release jobs could reuse the same working tree and corrupt branch/tag state.</risk>
    <risk>Old global announcement/version queries could expose another channel's release to APP users.</risk>
    <risk>Manual and automated release flows could diverge and create inconsistent checksum metadata.</risk>
  </risks>
  <mitigations>
    <mitigation>Require `channel_id` on announcements, app versions, engine versions, package verification, and release jobs.</mitigation>
    <mitigation>Generate short-lived job-scoped backend tokens and never log token values in worker output.</mitigation>
    <mitigation>Create a temporary directory per release job, delete it after completion, and use a per-channel/job lock.</mitigation>
    <mitigation>Worker sends `X-Apk-Channel` on upload/callback and backend verifies the job channel from server-side state.</mitigation>
    <mitigation>Use one shared checksum/file metadata path for manual emergency uploads and automated release jobs.</mitigation>
  </mitigations>
</threat_model>
