<threat_model>
## Trust Boundaries

| Boundary | Risk | Mitigation |
| --- | --- | --- |
| Admin browser -> backend `/authorization/open-url` | Super-admin-only remote browser access could expose authorized merchant backend sessions | Keep existing route/API super-admin gates and do not expose stream URLs to normal users |
| Backend -> crawler control service | Control service can open an already authorized merchant profile | Continue routing through configured control URL; avoid logging credentials or storage values |
| Crawler display recreation -> existing profile | Killing Chrome during display recreate could interrupt active work | Recreate only when size validation fails or a larger PC viewport is requested; preserve profile directory and do not delete cookies/tokens |
| `zhirang-dev` nginx proxy -> crawler dynamic ports | Wrong proxy target could expose or break streams | Use existing `/zr-stream/&lt;port&gt;/` routing and verify only required dynamic range |

</threat_model>
