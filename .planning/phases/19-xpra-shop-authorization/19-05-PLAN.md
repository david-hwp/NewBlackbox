<task type="auto">
  <name>Task 1: Add a VNC debug gate to the display startup script</name>
  <files>
    admin/scripts/browser/start-zr-display.sh
  </files>
  <action>
    Add an environment switch named `ZR_ENABLE_VNC`, defaulting to disabled. When the variable is unset, empty, `0`, or any value other than `1`/`true`/`yes`, `start-zr-display.sh` must not start `x11vnc`, must not create a new VNC password file for that run, and must not require the VNC port to be reachable.

    When `ZR_ENABLE_VNC=1` or equivalent truthy value, preserve the existing debug behavior: create/use `vnc.pass`, start `x11vnc` against the same `DISPLAY_ID`, bind it to `ZR_VNC_PORT`, and include it in listener diagnostics.

    In default-disabled mode, if a previous `x11vnc` process for the same display is still alive from an older run, stop it so legacy sessions do not keep exposing a VNC port after a display resize/reuse call.
  </action>
  <verify>
    <automated>bash -n admin/scripts/browser/start-zr-display.sh</automated>
    <manual>On the crawler server, run the display script for a fresh/reused session without `ZR_ENABLE_VNC`; confirm Xpra is reachable and no `x11vnc` process/listener exists for that display.</manual>
    <manual>Run the same display script with `ZR_ENABLE_VNC=1`; confirm `x11vnc` starts and listens on the expected VNC port.</manual>
  </verify>
  <done>
    - `ZR_ENABLE_VNC` exists and defaults to off.
    - Default Phase 19 admin/crawler sessions do not start `x11vnc`.
    - Xpra startup and resize/recreate behavior is unchanged.
    - Existing `x11vnc` for the target display is stopped when VNC is disabled.
    - Debug mode can still explicitly start VNC.
  </done>
</task>

<threat_model>

## Threat Model

| Threat | Severity | Mitigation |
|--------|----------|------------|
| VNC ports expose a second unaudited path to authorized merchant profiles | High | Disable VNC by default; start only when `ZR_ENABLE_VNC=1` is explicitly set for debugging. |
| Legacy VNC process survives after the default changes | Medium | Stop target-display `x11vnc` when the display script runs with VNC disabled. |
| Disabling VNC breaks Xpra or crawler flows due accidental coupling | Medium | Keep Xpra and CDP paths unchanged; verify management backend stream and crawler CDP separately. |
| Debugging becomes impossible when VNC is needed | Low | Preserve opt-in `ZR_ENABLE_VNC=1` behavior and VNC port diagnostics. |

</threat_model>
