<objective>
Implement the per-shop billing system. When a user launches a cloned app, the Engine extracts the shop ID asynchronously and notifies the main APK via AIDL. The main APK then checks for a valid token; if none exists or it has expired, it prompts the user to confirm point deduction, reports to the server, stores the returned token, and then allows the app to continue running.

Purpose: This is the revenue model. Every unique (user, platform, shop) combination requires a separate token. The system must be secure, user-friendly, and resilient against tampering.

Output: A working billing gate that intercepts all app launches, handles shop ID callbacks, manages token lifecycle, and integrates seamlessly with the login system from 06-01.
</objective>
