<objective>
Extend the existing Phase 19 remote-backend and Phase 21/23 scheduled order-ingestion chain so authorized Taobao Flash Sale / Ele.me (`tbwm`) shops can be detected from the PC merchant backend and collected every 30 minutes into `shop_orders`.
</objective>

<must_haves>
- PH23-D09: PC remote-backend authorization probing supports `tbwm` on `melody.shop.ele.me`, so an already authorized Ele.me profile is not misclassified as unauthorized only because the configured URL is the login page.
- PH23-D10: `tbwm` remote-backend opening uses the merchant backend home instead of the login URL, while authorization-login mode still opens the platform login URL when the user elects to authorize.
- PH23-D11: backend crawl-target eligibility includes authorized `tbwm` shops, using system `shops.id` and the same profile shop ID resolution as `mtwm`/`jdms`.
- PH23-D12: the scheduler dispatches `tbwm` targets to a dedicated Node/CDP collector without breaking the existing half-hour cron wrapper.
- PH23-D13: the `tbwm` collector uses Phase 19 profiles and submits through the existing `/shop-orders/ingest` contract; it must update the same row by `shop_id + platform + platform_order_id` when status changes.
- PH23-D14: `tbwm` order mapping fills existing identity/status/time/amount/customer/delivery/goods/raw business fields as far as the merchant page/API exposes them.
- PH23-D15: diagnostics and snapshots must not leak cookies, tokens, request headers, browser storage, profile paths, debug ports, or authorization probe signals.
- PH23-D16: implementation must be verified locally, then deployed only to the intranet/test topology and live-tested against the authorized `tbwm` 罗家臭豆腐 shop when SSH access is available.
</must_haves>
