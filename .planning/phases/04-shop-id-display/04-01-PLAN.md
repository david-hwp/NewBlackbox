  <action>
    Create `JDShopIdExtractor.java` implementing `ShopIdExtractor`:

    **getTargetPackage()**: return "com.jd.mrd.jingming"

    **extract(Context context, int userId)** — tries strategies in order, returns first successful ShopInfo:

    1. **Primary: SharedPreferences** (per D-03)
       - Build path via `BEnvironment.getXSharedPreferences("com.jd.mrd.jingming", "JingmingAndroidClient")`
       - Read XML file as text, parse for key `ge_tui_push_alias_bind_flag`
       - Value format: `16364870,true` — split on comma, first part is shopId
       - If found, return `new ShopInfo(shopId, null, "jd")`
       - Wrap in try-catch, log via Slog.d/Slog.w

    2. **Fallback: WebView DevTools** (per D-03)
       - Use `android.app.ActivityManager.getRunningAppProcesses()` to find PID of "com.jd.mrd.jingming"
       - If PID found, attempt to read `/proc/net/unix` for `webview_devtools_remote_{pid}` socket
       - If socket exists, use `adb localabstract` forward equivalent via `Runtime.exec("cat /proc/net/unix | grep webview")` or use `android.net.LocalSocket` to connect to the abstract socket
       - Alternative simpler approach: read `/proc/{pid}/net/unix` directly as file (requires root, may not work)
       - Simpler viable approach: Use `WebView.setWebContentsDebuggingEnabled` is controlled by app, not accessible from host. Instead, scan `/data/local/tmp/` or use `Runtime.getRuntime().exec("cat /proc/net/unix")` and parse output for webview socket names.
       - Most practical: Execute `sh -c "cat /proc/net/unix | grep webview_devtools_remote"` via Runtime.exec, parse output lines for PID matching JD process. Extract socket name. Then use `LocalSocketAddress` with `LocalSocketAddress.Namespace.ABSTRACT` to connect. Send HTTP GET `/json/list`, parse JSON response for `url` field. Extract `storeId` from URL query parameter.
       - If storeId found, return `new ShopInfo(storeId, null, "jd")`

    3. **Timeout guard**: Each strategy must complete within 5 seconds total. Use a simple timeout mechanism (future/cancel or elapsed time check).

    4. **Logging**: Use Slog.d for normal flow, Slog.w for failures, Slog.e for exceptions. Tag = "JDShopIdExtractor".

    **Important constraints**:
    - Do NOT modify any app data — read-only operations only
    - Do NOT assume debuggable flag on target app
    - Handle all exceptions gracefully — return null on any failure
    - The SharedPreferences path is the most reliable; optimize for it

    For the WebView DevTools strategy, since direct LocalSocket connection from the host app to the virtual app's webview socket may have permission issues, implement a pragmatic approach:
    - Try to find the JD process PID via ActivityManager
    - If found, try Runtime.exec to run `run-as top.niunaijun.blackbox sh -c "cat /proc/net/unix | grep webview"` — this gives socket names
    - Parse socket name, then attempt connection
    - If all WebView approaches fail, log and return null (no third fallback per scope — Logcat last resort is deferred)
  </action>
