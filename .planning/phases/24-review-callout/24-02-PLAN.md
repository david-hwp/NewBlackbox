<objective>
Add the review-callout result callback pipeline: accept authenticated Gooki call-result pushes, correlate them to local orders, deduct user phone balance exactly once according to configured billing rules, and expose the resulting `PHONE_CONSUME` ledger entries in the APP and management backend.
</objective>

<must_haves>
- PH24-D11: external callback endpoint with independent token/signature auth and Gooki-compatible success response.
- PH24-D12: callback correlation primarily by local callout/order identity carried in Gooki `params`, never by customer text alone.
- PH24-D13: persisted external call-result/CDR detail with call state, duration, billed minutes, external money, grade, remark, and sanitized payload summary.
- PH24-D14: duplicate callbacks and retries do not duplicate deductions or transaction logs.
- PH24-D15: phone-balance deduction is driven by actual call result and configurable fee rate.
- PH24-D16: successful deductions create precise `PHONE_CONSUME` transaction logs.
- PH24-D17: unmatched callbacks and insufficient balance are stored and visible without negative balances.
- PH24-D18: APP transaction logs can show and filter “话费消耗”.
- PH24-D19: management backend transaction logs can show and filter “话费消耗” with enough shop/order/callout detail for audit.
</must_haves>

<title>Correlate callback results and deduct phone balance idempotently</title>
<read_first>

- `.planning/phases/24-review-callout/24-CONTEXT.md`
</read_first>
<action>
Implement result processing and billing:
- Create `ReviewCalloutCallbackService` to:
  - Build an idempotency key from `external_cdr_id`; fallback to `external_task_id + local_callout_id + phone_hash + call_time`.
  - Find the local `ShopOrderReviewCallout` by `review_callout_id` from `params`.
  - Validate `shop_order_id`, `shop_id`, platform order ID, and external task ID when present.
  - Fallback to `shop_order_id` from `params` only when the outbox row still matches the same order.
  - Mark unmatched callbacks as `UNMATCHED` and store diagnostics without billing.
- Create `ReviewCalloutBillingService` to:
  - Classify billable results from configured connected states; default billable when `callState=2` or equivalent connected status.
  - Use `billed_minutes` from callback when present; otherwise compute `ceil(duration_seconds / 60.0)` for connected calls.
  - Compute deduction as `max(minimum_charge_units, ceil(billed_minutes * rate_units_per_minute))` by default.
  - Store external `money` as audit evidence; only use it for deduction when `app.review-callout.billing.mode=EXTERNAL_MONEY` is explicitly configured.
  - Run deduction and transaction-log creation in one database transaction.
  - Refuse to deduct if user balance is insufficient; mark result `INSUFFICIENT_BALANCE` and do not make balance negative.
- Add or reuse a `ComputeService` method for phone-balance consumption:
  - operation key/idempotency key required.
  - updates `users.phone_minutes_balance`.
  - creates one `TransactionLog` type `PHONE_CONSUME`.
  - fills `userId`, `channelId`, `platform`, `shopName`, `amount`, `remark`, `shopOrderId`, `reviewCalloutId`, `externalTaskId`, `externalCdrId`, `calledAt`, and `billingRate`.
- Ensure duplicate callbacks:
  - return success to the external system.
  - update non-billing diagnostic fields when safe.
  - never create a second `PHONE_CONSUME` row for the same idempotency key.
</action>
<acceptance_criteria>
- A connected callback with valid params deducts the configured amount once and writes one `PHONE_CONSUME` log.
- Replaying the exact same callback does not change balance and does not create a second log.
- A non-connected callback is stored as `NOT_BILLABLE` and does not deduct.
- A callback with missing or mismatched local identity is stored as `UNMATCHED` and does not deduct.
- Insufficient phone balance stores `INSUFFICIENT_BALANCE`, creates no consume log, and never makes the user balance negative.
- The transaction-log remark or relationship fields identify shop, order, callout row, CDR ID, call time, billed minutes, rate, and amount.
- Tests prove billing mode, rounding, minimum charge, duplicate callback, insufficient balance, and unmatched callback behavior.
</acceptance_criteria>
